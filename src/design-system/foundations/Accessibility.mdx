# Accessibility

The site meets **WCAG 2.2 AA** and aims for **AAA** where practical. The Accessibility panel runs axe on every story with the same tags as `src/routes/a11y.e2e.ts` (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, `best-practice`). Open checks are tracked in `docs/accessibility-audit.md`.

## Built into the components

- **Contrast (1.4.6, AAA):** body text pairs are 7:1 or more. Primary button text is {contrast(value('--color-text-on-dark'), value('--color-action'))}:1 on `--color-action`; accent text on dark is {contrast(value('--color-accent-on-dark'), value('--color-surface-brand'))}:1. See Foundations / Colour.
- **Focus:** a 2px `--color-focus` outline, offset 2px, on `:focus-visible`. On dark it switches to `--color-accent-on-dark`. Never remove it.
- **Targets (2.5.5, AAA):** interactive controls are at least 44 × 44px: small buttons, nav links, the menu button and form inputs set `min-height: 2.75rem`.
- **Works without JavaScript:** the mobile menu is a native `popover`; FAQs and audience panels are `<details>`; the form posts natively.
- **Landmarks and names:** every `Section` is named by its `<h2>` through `aria-labelledby` (1.3.6). Regions without a visible heading get `aria-label`.
- **Skip link** to `<main>`, which takes focus.
- **Icons are `aria-hidden`**; links that open a new tab say so (`NewTabHint`); "Request a free site assessment" buttons repeated per audience add visually hidden context.
- **Forms:** visible labels with "(required)", hints linked with `aria-describedby`, errors set `aria-invalid` and are listed in a focused summary with links to each field (see Sections / EnquiryForm / With errors).
- **Reduced motion** is respected.

## Utilities

- `.visually-hidden` hides text visually but keeps it for screen readers.
